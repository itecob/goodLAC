The problem

Keep proposal separate from permission

AI agents increasingly request consequential actions. The model can express intent, but it should not become the permission system or the executor. goodLAC places a deterministic control boundary between an agent harness and the effects it may request.

Agent / harness→goodLAC→policy · identity · approvals · leases→bounded effect

What goodLAC provides

A controller-owned authority boundary

Deterministic authority

Capability registration, policy, identity, exact approvals, and deny precedence are evaluated by the controller.

Bounded effects

Policy is re-evaluated before dispatch, with leases, idempotency, durable receipts, and effect truth.

Interruptible operation

Emergency pause and fail-closed handling keep consequential execution under explicit owner and system control.

Separated credentials

Credentials and privileged executors remain outside the untrusted model or agent context.

What this manual covers

This documentation applies specifically to 1.0.0-rc.12, the first goodLAC release intended for ordinary public use. It covers the qualified Linux reference path, default-governed Pi, project identity, permissions, owner administration, provider and external-consumer boundaries, security architecture, durable effect truth, troubleshooting, rollback, licensing, support, and public project policy.

Qualified reference path

  • Linux reference platform.
  • Pinned Pi 0.85.1 reference harness.
  • Four model-facing consequential tools: lac_fs_read, lac_fs_create, lac_fs_replace, and lac_shell_exec.
  • Controller-owned policy, approvals, identity, leases, receipts, emergency state, and capability registry.
  • Explicit dangerous bypass for owner/debug use; that path is not governed.
