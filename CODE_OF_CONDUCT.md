# Code of Conduct

## Purpose

goodLAC is intended to support serious technical discussion about agent authority, security, permissions, integrations, deployment, and related product behavior.

ITECOB Inc. wants the repository's public collaboration spaces to remain useful, professional, and safe for participants.

## Expected conduct

Participants are expected to:

- discuss technical disagreements on their merits;
- provide reproducible evidence where practical;
- distinguish facts, observations, assumptions, and opinions;
- avoid knowingly misleading claims;
- respect privacy, credentials, security boundaries, and responsible-disclosure requirements;
- avoid harassment, threats, personal attacks, discriminatory abuse, or sustained disruptive behavior;
- avoid publishing another person's private information without permission;
- avoid posting undisclosed vulnerability details in public channels; and
- follow GitHub's applicable Terms of Service and community policies.

Strong criticism of software, architecture, security claims, documentation, or project decisions is permitted. Criticism should remain directed at the work rather than at a person's inherent characteristics or dignity.

## Scope

This Code of Conduct applies to public goodLAC repository spaces controlled by ITECOB Inc., including issues, Discussions, pull requests, review threads, and other project-managed communication surfaces.

It does not convert the repository into an open-contribution project. External code and other copyrightable contributions are currently closed as described in [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Security reports

Do not disclose an undisclosed vulnerability through a public issue, Discussion, or pull request.

Use GitHub Private Vulnerability Reporting through the repository's Security interface as described in [`SECURITY.md`](SECURITY.md).

## Enforcement

ITECOB Inc. may edit, hide, lock, close, or remove project content, or restrict participation in project-managed spaces, when reasonably necessary to enforce this Code of Conduct, protect participants, preserve security, or keep project communication usable.

Enforcement decisions may consider context, severity, repetition, intent, and impact.

## Reporting conduct concerns

Where GitHub provides a built-in report or moderation mechanism, participants may use it.

For a conduct concern that requires direct project-owner attention and is not a vulnerability report, contact:

**support@itecob.com**

Do not send vulnerability details to that address unless ITECOB Inc. expressly directs you to do so; use the private security-reporting process instead.

## No support commitment

Participation in project discussion does not create a support, response-time, maintenance, or service-level commitment from ITECOB Inc. See [`SUPPORT.md`](SUPPORT.md).
